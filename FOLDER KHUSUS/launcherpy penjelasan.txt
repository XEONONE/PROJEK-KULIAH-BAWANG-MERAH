BLOK 1: IMPORT PUSTAKA DASAR & PENGATURAN LOGGING
====================================================================================================
```python
import os
import sys
import time
import subprocess
import threading
import logging
import tkinter as tk
from tkinter import ttk, messagebox

BASE_DIR = os.path.dirname(os.path.abspath(__file__))
LOG_FILE = os.path.join(BASE_DIR, "app_error.log")

logging.basicConfig(
    filename=LOG_FILE,
    level=logging.INFO,
    format="%(asctime)s [%(levelname)s] (LAUNCHER) %(message)s",
    datefmt="%Y-%m-%d %H:%M:%S"
)
```
PEMAHAMAN KRITIS:
- Mengapa menggunakan pustaka bawaan (built-in)? 
  Berbeda dengan app.py, launcher.py SANGAT DILARANG menggunakan pustaka eksternal pihak ketiga
  (seperti cv2 atau tensorflow) pada bagian awal kode (import). Jika ia menggunakan pustaka eksternal,
  maka launcher akan langsung "Crash/Error" sebelum sempat mendiagnosa karena pustaka tersebut
  belum tentu terinstall di komputer penguji. Semua modul yang di-import di atas adalah modul
  wajib bawaan bahasa Python (Standard Library).
- `subprocess`: Modul yang sangat vital di sini. Ini ibarat tangan maya yang akan mengetikkan
  perintah di terminal (CMD) secara diam-diam (seperti perintah 'pip install ...').
- `logging.basicConfig`: Menyiapkan alat pencatat otomatis. Tag `(LAUNCHER)` disematkan agar di
  dalam file log kita bisa membedakan mana error yang terjadi saat "Booting" (launcher) dan
  mana error yang terjadi saat "Analisis" (app.py).

BLOK 4: FUNGSI KOMUNIKASI VISUAL (CETAK LOG KE LAYAR)

```python
    def log_to_ui(self, msg, color="#ffffff"):
        self.log_area.config(state='normal')
        self.log_area.insert(tk.END, msg + "\n")
        
        # Mencari baris terakhir yang diisi
        last_line = self.log_area.index("end-2c").split(".")[0]
        self.log_area.tag_add(f"color_{last_line}", f"{last_line}.0", f"{last_line}.end")
        self.log_area.tag_config(f"color_{last_line}", foreground=color)
        
        self.log_area.see(tk.END)
        self.log_area.config(state='disabled')
        self.root.update_idletasks()
```
PEMAHAMAN KRITIS:
- Fungsi `log_to_ui` adalah pengganti perintah `print()` biasa.
- Sistem harus membuka gembok area teks (`state='normal'`), memasukkan teks, mewarnai baris tersebut
  sesuai level (Kuning, Hijau, Merah, dsb), lalu menggemboknya kembali (`state='disabled'`).
- `self.log_area.see(tk.END)`: Sangat penting! Ini memaksa layar terminal selalu menggulir (scroll) 
  ke baris paling bawah. Jika ini tidak ada, proses analisis yang panjang akan tertutup di bagian
  atas kotak dan pengguna tidak tahu apa yang sedang terjadi di bawah.
- `update_idletasks()`: Memaksa komputer segera me-refresh kartu grafis (GPU/Layar) saat itu juga.
  Tanpa ini, animasi di layar Tkinter akan "Macet" (Freeze) selama program memikirkan diagnostik.

```python
    def mulai_diagnostik(self):
        # Jalankan di thread terpisah agar UI tidak freeze
        threading.Thread(target=self._jalankan_diagnostik, daemon=True).start()

    def _jalankan_diagnostik(self):
        # TAHAP 1: CEK PYTHON VERSION
        if sys.version_info < (3, 8): ...
        
        # TAHAP 2: CEK LIBRARY DEPENDENSI
        to_install = []
        for imp_name, pip_name, desc in PACKAGES:
            try:
                __import__(imp_name)
                self.log_to_ui(f" [OK] {desc} ({pip_name}) terdeteksi.", "#2ecc71")
            except ImportError:
                to_install.append(pip_name)
                self.log_to_ui(f" [WARNING] {desc} tidak ditemukan. Akan diinstall.", "#f1c40f")
        ...
```
PEMAHAMAN KRITIS:
- `threading.Thread(..., daemon=True)`: Sama seperti di app.py. Jika `_jalankan_diagnostik` 
  berjalan di alur utama (main thread), maka Progress Bar dan kelip-kelip teks akan membeku. 
  Thread adalah solusi multatasking. `daemon=True` memastikan thread ini otomatis bunuh diri
  apabila jendela launcher ditutup paksa (X) oleh pengguna.
- Logika `__import__(imp_name)`: Menggunakan metode ajaib (magic method) python. Ia mencoba 
  menarik modul ke memori. Jika Python menjawab "ImportError" (tidak ketemu), maka sistem 
  langsung memasukkan nama pip-nya ke antrian `to_install`.

BLOK 6: AUTO-INSTALLER (MEKANISME SELF-HEALING)
====================================================================================================
```python
        if to_install:
            self.log_to_ui(f"\n> MEMULAI INSTALASI OTOMATIS: {len(to_install)} modul...", "#00d2ff")
            try:
                subprocess.run(
                    [sys.executable, "-m", "pip", "install"] + to_install,
                    check=True, stdout=subprocess.PIPE, stderr=subprocess.PIPE
                )
                self.log_to_ui(f" [SUKSES] Seluruh modul berhasil diinstall!\n", "#2ecc71")
            except subprocess.CalledProcessError as e:
                self.log_to_ui(f" [ERROR] Instalasi gagal: {e}", "#e74c3c")
                self.root.after(0, lambda: self.btn_launch.config(state="disabled"))
```
PEMAHAMAN KRITIS:
- `subprocess.run`: Ini adalah "Jurus Rahasia" dari script ini. Ia tidak memanggil "pip" biasa.
- Mengapa `sys.executable`? Pada sebuah PC, seringkali ada banyak versi Python yang bertabrakan 
  (misal Python 3.8 dan Python 3.10). `sys.executable` akan mendapatkan rute pasti letak Python 
  mana yang *sedang* membuka jendela saat ini. Hal ini memastikan modul tidak "nyasar" ke 
  instalasi Python versi lain yang ada di laptop penguji.
- Bila perintah CMD ini gagal (`CalledProcessError`), misalnya karena tidak ada internet, 
  tombol hijau luncurkan aplikasi (btn_launch) akan di-matikan secara permanen (`disabled`).

BLOK 8: SISTEM LUNCURKAN APLIKASI (TRANSISI PERTUKARAN ROH/PROSES)
====================================================================================================
```python
    def luncurkan_app(self):
        try:
            self.root.destroy()
            app_path = os.path.join(BASE_DIR, "app.py")
            os.execv(sys.executable, [sys.executable, app_path])
        except Exception as e:
            messagebox.showerror("Launcher Error", f"Gagal meluncurkan aplikasi utama:\n{e}")
```
PEMAHAMAN KRITIS:
- Logika eksekusi: Tombol Hijau ditekan.
- `self.root.destroy()`: Menghancurkan jendela Launcher dari memori. Ia pamit mundur diri.
- `os.execv()`: Ini adalah bagian komputasi tingkat rendah (Unix/Windows system call).
  Ia TIDAK memanggil "subprocess" (membuka terminal baru). Fungsi `execv` akan mengeksekusi script
  app.py, kemudian mentransfer total sisa napas proses ID (PID) launcher.py saat ini kepada app.py.
  Sederhananya: "Tubuh" proses launcher diubah menjadi "Tubuh" app.py dalam satu jalur memori.
  Ini sangat efisien dan mencegah adanya proses zombie / penumpukan aplikasi ganda di background Task Manager.
